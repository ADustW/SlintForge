### 缓存与缩放定位

`cache-comparison-idle/result.json` 使用同一隔离 Rust 程序，仅切换旧正文缓存策略，按关／开／开／关／关／开的顺序执行。关闭时三次缩放帧 P95 为 19.6023／18.8340／19.9341ms，开启时为 23.4403／19.9508／24.7689ms；整体帧 P95 的范围相近，没有稳定收益。这些诊断记录显式标记为不可用于正式验收。

隔离程序将缩放输入分开计时。关闭缓存时，指针事件 P95 为 1.7730～2.0510ms，滚轮事件 P95 为 5.9588～6.2074ms；开启时分别为 2.1367～2.9155ms、6.2735～7.6410ms。开销主要落在滚轮事件处理这一段，包含视口更新、属性求值及事件处理；这里没有进一步拆出每段 CPU 或 GPU 等待，不能假称已经获得完整火焰图归因。当前正式版本缩放已满足目标，继续保留直接绘制正文，避免追加未经证明的缓存。

软件渲染的 53 步切换文档和连线截图对照见 `cache-repaint-comparison/result.json`，本次开／关两组均通过。该短场景没有重新复现先前缓存残留；诊断副本增加了全局缓存开关依赖，这不能证明生产环境中已修复原来的失效问题。此前失败截图及当前生产版本的 12 组合／96 项连线连续性验证继续保留于 `build/flow-routing-review-20261014/`。

### 内存与尚未完成的范围

`lifecycle/result.json`：两端各 1379 步、900 次编辑、100 步历史、60 次画布重建及 64 次控制器释放通过。C++／Rust 持续 146.10／142.96 秒，私有内存峰值 901.37／901.91MiB；重建阶段为 446.38→443.16／436.95→451.73MiB。两端峰值都出现在历史编辑阶段。相比前一轮的 908.82／866.77MiB，没有证据表明缓存回退降低了总体内存开销；隔离短场景的缓存开关峰值也不能替代完整编辑场景。

## 审查结论

原实现已经具备节点、端口、编辑历史、数据保存和思维导图等核心能力，但与 Vue Flow 相比，日常操作入口、节点选中反馈、连线外观扩展和示例表达明显不足。旧界面的两排固定工具栏挤占画布，标题与卡片正文的视觉关系松散；多数页面重复同一种节点链，无法清楚展示流程分支和设备网络的用途。

本轮优先补齐可直接使用的编辑操作和组件组合能力，并重做 Flow 自身的视觉令牌。以下“已验证”只指本轮记录中的窗口、接口和性能场景，不代表 Vue Flow 全部生态功能已经移植。

## 仍有差距的部分

- **通用图嵌套分组**：Vue Flow 有 [父子节点示例](https://vueflow.dev/examples/nodes/nesting.html)。ForgeFlow 的 `parent` 当前用于思维导图树；普通图没有分组容器、父节点约束拖动及组内坐标，不能将树父级当成已支持分组。
- **对齐辅助与通用自动布局**：尚无拖动参考线、等距辅助，也未接入 Dagre／ELK 一类通用布局。当前仅思维导图提供确定性自动布局；流程图和拓扑图采用手动布局及示例初始坐标。
- **高级边效果**：本轮支持静态虚线，没有流动动画、任意 Marker 图形、多段用户控制点。拖动连接的临时引导线仍为直线；提交后按所选线型和避障路径绘制。
- **画布边缘自动平移**：拖动节点或连线到边缘时尚不自动平移；可使用中键、空格或平移工具继续导航。
- **无障碍及键盘覆盖**：工具按钮已有标签、焦点及键盘触发；图节点仍以鼠标交互为主，没有宣称与完整 Web 可访问性行为对齐。

这些差距属于独立功能，不以新外观或编译通过标记为完成。
