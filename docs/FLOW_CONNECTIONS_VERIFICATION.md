# ForgeFlow 连线与样式增量验收

日期：2026-10-13。本次范围为 ForgeFlow 连线几何、样式编辑、双语言 SDK 和五个 Gallery 接入页面。保留原工作区修改，没有逐页重跑其他组件。

## 问题与修正

截图中的节点 3 → 节点 4 使用折线，原算法直接以两端坐标中点转向，导致路径向卡片内部回折并被遮挡。现在按两端端口朝向引出／进入，检查卡片遮挡并尝试外侧通道；曲线受遮挡时使用圆滑的绕行路径。标签、连线命中和适应范围跟随最终几何。移动卡片时，也会刷新受影响的非相邻连线，未改变的模型行不更新。

选中已有连线后，可在内置面板修改直线／曲线／折线、1～8 的线宽、箭头及标签；支持多选批量应用、一步撤销、重做和 JSON 保存加载。示例顶部线型下拉框同时支持修改选中连线；未选择连线时设置后续新建的默认线型。只读模式禁用修改。两处下拉框与撤销后的属性回显已显式同步。

C++／Rust 提供 `update_edge_appearance`，只更新指定外观，保留端点、ID 和扩展数据。旧 JSON 缺少线宽时默认为 2。运行库操作编号不变，接口指纹随共享模型更新，旧 DLL 不匹配时明确报错。

## 检查结果

最终证据：`build/flow-connections-final-validated/result.json`，26 项检查通过。

- C++：128 组方向／位置／线型组合，另测六组相邻及近乎重合端口、障碍节点移动、路径命中、400% 下粗线命中、样式校验、撤销和保存加载。500 节点／1000 连线的核心拖动调用 P95 为 1.892 ms。
- Rust：3 项 Flow DLL 测试通过，覆盖样式更新、Unicode、数据隔离、历史及序列化；4 项运行库兼容测试通过。
- 两端各通过既有 114 步编辑流程，保留连接、重连、输入卡片和撤销等交互。
- 两端分别在 `winit-skia`、`winit-skia-software` 和 100%／150%／200% 应用缩放下运行 49 步连线样式交互，共 12 组通过，包含深浅主题、窄窗口及只读模式。
- Gallery 每端只检查五个 Flow 页面，共 15 个主题／语言／窗口状态；导航搜索和离开返回后的状态保留通过。
- 共享绑定、运行库接口生成、第一方 C++ namespace 检查和差异空白检查通过。

窗口事件通过 Slint 的真实窗口接口分发，覆盖实际命中、焦点、弹层与绘制；此处应用缩放不等同于人工调整 Windows 全局 DPI。

## 性能

机器：AMD Ryzen 9 9955HX（16 核／32 线程），NVIDIA RTX 5060 Laptop GPU，驱动 `32.0.15.7709`。Slint 1.18.0、Rust 1.98.0、Release，使用既有 CLion 环境。窗口 1100×760 物理像素，100% 应用缩放。每种场景包含 500 节点、1000 连线，预热后连续执行节点拖动、平移和缩放。

| 宿主／渲染器 | 卡片 | 帧样本 | 帧间隔 P95 | 输入反馈 P95 |
| --- | --- | ---: | ---: | ---: |
| C++ / Skia OpenGL | 标准 | 607 | 14.697 ms | 15.416 ms |
| C++ / Skia OpenGL | 混合 | 581 | 15.995 ms | 16.955 ms |
| Rust / Skia DX12 | 标准 | 572 | 16.149 ms | 16.401 ms |
| Rust / Skia DX12 | 混合 | 530 | 17.823 ms | 17.679 ms |

四种场景均满足 P95 帧间隔 ≤33 ms、反馈 ≤100 ms。原始记录位于 `build/flow-connections-final-validated/cpp-performance/`、`rust-performance/`。帧间隔为相邻渲染完成回调间隔，反馈为窗口输入到下一次渲染完成；不是屏幕实际呈现延迟。节点可见性裁剪仍然启用。

C++ 默认 DX12 已通过交互矩阵；当前官方 DLL 的该路径没有提供可用帧回调，因此 C++ 性能仅报告显式 OpenGL 路径，不能将其标成 DX12 的性能结果。
