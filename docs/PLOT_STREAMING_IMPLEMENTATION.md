# ForgePlot 实时绘图与交互补齐

本轮目标：多类型坐标轴、多条曲线独立绑定 Y 轴、静态批量数据与逐点追加、八种图例位置及样式、最新值、固定窗口及无限历史滚动、缩放、光标测量、曲线样式，以及保留峰谷特征的可见范围抽样。

## 已完成的修复

- Gallery 的“图表”菜单第一个子页面为 `ForgePlot`，英文菜单为 `Chart → ForgePlot`；路由为 `chart-professional`。
- 旧示例每 33 ms 发布整个 2000 点模型，重新复制历史，停止再启动时重置时间。现改为引擎保留历史、批量增量追加；两条曲线使用同一连续采样时间。
- 旧缓冲区丢弃点后，固定参考线仍停留在 0–5 秒，自动 X 范围覆盖两者，形成长空白。现两条实时曲线同步追加；默认无限历史模式按 10 秒跨度跟随最新数据，并允许滚动回看。
- 数据范围增量维护；有序曲线二分定位可见范围。纯 XY 折线的分层摘要加速每像素桶的首点、末点、峰、谷抽样，不丢弃原始数据。
- `append-point/append-points` 合并帧刷新，默认间隔 16 ms；`flush()` 可立即读取最新场景。图例、样式和视图修改保留追加历史；临时无效轴配置恢复后也保留历史。
- 静态模型、增量输入、图例配置与视图操作使用相同引擎，Rust/C++ 共享契约。两端 SDK 提供 f64 追加和原始点测量接口。

## 性能实测

验收环境：Windows x64、Slint 1.18.0、`winit-software`，独立示例窗口 1080 × 760。Rust 使用 Debug 配置，外部绘制依赖启用优化、共用 C++ 引擎启用优化；C++ 使用 Release。两端数值用于各自当前配置的帧预算验证，不作为语言间性能比较。

输入为单条有序 XY 曲线的 100 万点历史，显示最近 10 秒；随后每帧追加 32 点，共记录 64 帧。完整帧包括追加、场景准备和完整窗口软件绘制/截图，不含显示器呈现延迟。

| 宿主 | 完整帧中位数 | 完整帧 p95 | 追加中位数 | 追加 p95 |
|---|---:|---:|---:|---:|
| Rust | 23.126 ms | 27.526 ms | 0.048 ms | 0.058 ms |
| C++ | 15.439 ms | 16.116 ms | 0.020 ms | 0.025 ms |

两端完整帧 p95 均在示例 33 ms 更新周期内；验收脚本门限为完整帧 p95 < 50 ms、追加 p95 < 5 ms，且显示抽样点数 < 5000。首批追加可能触发容器扩容，因此以完整 64 帧的中位数和 p95 报告，并保留所有原始样本。

核心引擎的 100 次百万点历史窗口绘制中位数为 1.062 ms、p95 为 1.341 ms。另一组全范围百万点对照：关闭自适应绘制 100 万点耗时 527.06 ms，开启自适应绘制 2462 点耗时 3.318 ms；这是两种绘制配置的对照，不等于旧版本到新版本的加速比。

真实定时采样完成暂停恢复流程后，Rust 保留 4706 点、C++ 保留 4694 点，均为两条曲线的合计。点数差异来自实际运行时间；两端均验证每点 X 与原始索引对应、最早数据保留、10 秒窗口跨度和恢复后时间连续。

## 使用边界

无限和固定窗口均保留原始历史，内存随点数增长；固定模式仅限制显示跨度。需要有界内存的应用可使用 SDK 中的 `PlotBuffer/ForgePlotBuffer`。

有序纯 XY 折线获益于增量摘要和二分裁剪。乱序折线追加需要重建排序；参数曲线保留原始顺序；断点、误差、选择及不满足摘要条件的数据回退到逐点处理。百万点性能结果对应上述有序折线配置，不外推到所有图形组合。

API、坐标轴绑定和示例用法见 [`PLOT.md`](PLOT.md)。
